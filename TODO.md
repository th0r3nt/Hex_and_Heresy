## 1: Ядро - Чистый Python
Дописываем models.py (Pydantic). Описываем поле боя, карточки, гексы.
Пишем механику перемещения и расчета характеристик без LLM и UI. (Просто консольный ввод-вывод или простые скрипты).
Пишем логику генерации и обновления состояния WorldState.

## 2: LLM Конвейер - LLM + Python
Пишем client.py (асинхронная обертка над OpenAI/Anthropic/локальным Ollama-API).
Реализуем builder.py (сборка системного промпта из .md файлов).
Настраиваем первый Function Calling: заставляем Оружейника (Gunsmith) вернуть правильный JSON чертежа алебарды на основе текста.

## Этап 3: Мост - Python + FastAPI + WebSockets
Оборачиваем наше ядро в локальный сервер.
Учим бэкенд отправлять JSON с картой и принимать команды (например, {"action": "move", "unit": 12, "target": [3, 4]}).

## Этап 4: Интерфейс - Electron + TypeScript + HTML/CSS
Строим сетку (Layout).
Рендерим гексагоны (лучше всего использовать SVG или HTML5 Canvas).
Подключаем окна диалогов и красивые шрифты.

### Ожидаемый процесс запуска игры 
1. Базовый запуск
    * Запуск EXE: Пользователь запускает файл "Hex & Heresy.exe". ОС распаковывает приложение в память. Точкой входа является главный процесс Electron (написанный на JS/TS).
    * Экран загрузки: Electron сразу открывает красивое окошко с логотипом игры и надписью «Загрузка мира...», чтобы пользователь понимал, что игра не зависла.
    * Запуск Бэкенда: Ключевой момент. Electron в фоновом режиме операционной системы, запускает Python-бэкенд как дочерний процесс.

2. Инциализация бэкэнда
    * Сборка контейнера: FastAPI считывает переменные окружения, поднимает подключение к локальной SQLite.
    * Инициализация интерфейсов: Приложение связывает абстрактные интерфейсы с реальным кодом. Передает HTTP-клиент для LLM внутрь ChroniclerService, GunsmithService и GameMasterService.
    * Запуск Event Bus: Поднимается локальная шина событий.
    * Старт сервера: FastAPI начинает слушать локальный порт.

3. Рукопожатие
    * Healthcheck: Electron-процесс каждые полсекунды стучится на локальный порт..
    * Подключение: Как только FastAPI отвечает HTTP 200, Electron понимает, что бэкенд готов.
    * Рендеринг UI: Electron закрывает сплеш-скрин и открывает главное окно игры на весь экран, загружая src/front/utils/index.html.

4. Главное меню и вебсокет
    * Загрузка фронта: Выполняется TypeScript. Отрисовывается Главное меню.
    * Установка связи: TypeScript-клиент устанавливает постоянное WebSocket-соединение с бэкендом. Это вечный канал связи, по которому будут летать JSON-ы с состоянием карты и ответами LLM.
    * Ожидание: Игра ждет действий пользователя.

## Как визуализировать юнитов со своей экипировкой (броня, оружие, акссесуары)?
Представим классическую карточку. Само изображение на карточке - это её основа (например, изображение классического гоблина). И сверху слева от карточки есть три ячейки - соответственно, броня, оружие и аксессуар.
Если игрок захочет создать кастомную карточку - гоблины с костяными кирками и базовой броней - на выходе он увидит карточку с гоблинами, а вот слева сверху в ячейках будет лежать сооветствующая экипировка.
Говоря про поле боя (тактическую карту) - игрок просто будет перетаскивать карточки.
